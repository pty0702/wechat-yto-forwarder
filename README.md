# 微信 ⇄ 圆通客户管家消息转发

Python 桌面工具：按运单号和关键词处理微信群文本，将请求转到客户管家，再将机器人的相关回复搬回微信。

## 当前可用内容

- 中文配置窗口，启动、停止、实时日志和独立演示。
- YT 运单筛选、屏蔽词、@客服分流、完整机器人昵称匹配、30 秒静默超时。
- 消息事件去重、发送失败缓存、发送结果不确定时停止，避免盲目重发。
- Windows UI Automation 适配器、窗口诊断、双端适配检查、启动历史基线、目标群与进程锁定、发送回显检查。
- 微信 4 临时进入多选读取发送者，以完整 RuntimeId 和完整正文严格映射，恢复普通态后再接纳消息。
- 微信 4 原生提及候选核验、草稿与回显分别检查，以及带发送前预览的单条测试入口。
- 默认关闭的实验性微信兼容选项：仅对已核对的固定构建临时激活无障碍控件。

**首次真实双端准备检查已通过，实际发送和真实 @ 尚未验收。** 2026-10-23 在本机微信 `4.1.15.56` 的固定构建上，已验证无障碍控件临时激活与恢复、多选态发送者提取，以及恢复后完整 RuntimeId、正文和顺序一致。该结果不代表支持任意微信 4.x。

客户管家 `2.0.0.2` 的输入框已完成“空输入 → 自有测试草稿完整回读 → 清除后恢复空输入”的验证。限定配置可将 `edit-content` 空叶的单个 `U+FFFC` 识别为空；混合占位符、有子节点或不符的控件仍拒绝。仓库中的 `uia.example.json` 是需要按本机诊断调整的配置示例。

实验性兼容会临时修改已核对微信进程的无障碍状态字节，不修改客户端磁盘文件，不读取聊天数据库。正常结束、停止及可控异常会执行恢复；强制结束或崩溃时无法保证恢复，需重启微信。兼容功能另外要求 64 位 Windows 和 64 位 Python。

## 启动

需要 Windows、Python 3.9+（含 Tkinter）和 PowerShell 7。在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\python版\requirements.txt
.\.venv\Scripts\python.exe -X utf8 .\python版\gui.py
```

已有虚拟环境时，也可使用项目内的 `启动.ps1`。

界面默认选择演示模式，点击“开始运行”可查看约 12 秒的内置案例。演示只在内存处理样例，不需要真实群，也不会保存样例配置。

按 `Ctrl+D` 启动窗口诊断，5 秒内手动将焦点放回待检查输入框。需要上述固定构建的兼容功能时，先勾选默认关闭的“微信4兼容（实验性，停止后恢复）”。

填好真实配置并选择本地适配文件后，按 `Ctrl+T` 执行“适配检查”：核对两端目标群、草稿读取和消息来源，建立历史基线，然后退出；微信可能临时进入多选，**不会键入或发送消息**。看到“检查与恢复已完成”只表示准备就绪。

点击“单次发送验收…”可选择一端，核对目标群与固定测试文本后再发送，微信端可选真实 @。每次只发一条，结束后停止；失败不自动重试。准备检查和单次验收均把结果保存在本地 `diagnostics/live-check-*.json`。实际转发、回流和 @ 应分别验收，完整步骤见下方 Python 版说明。

## 验证

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s .\python版\tests -v
.\.venv\Scripts\python.exe -X utf8 .\python版\wechat_forwarder.py
```

自动化测试覆盖业务规则、模拟控件、多选身份映射、客户管家空叶输入、诊断取消、发送确认和兼容会话恢复，不替代真实客户端收发验收。

详细业务规则、适配配置格式、已知限制与诊断说明见 [Python 版说明](python版/README.md)。
