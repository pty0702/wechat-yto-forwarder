# 微信 ⇄ 圆通客户管家 消息搬运（Python 版）

由原易语言程序（`新建文件夹/1232.exe` 内嵌资源）逆向还原业务逻辑后，用 Python 重写的核心实现。
只保留业务工作流，不含原程序的大漠插件、找图找色、窗口句柄绑定等实现细节。

## 业务逻辑

### 方向① 微信 → 客户管家

只看**以 YT 运单号开头**的客户消息，按顺序判定：

| 顺序 | 条件 | 动作 |
|---|---|---|
| 1 | 含**屏蔽词**（自己配置） | 装作没看见，直接忽略 |
| 2 | 含 **@客服词句**（自己配置） | 在微信群发 `@客服名 + 原话`，**不**转发小圆 |
| 3 | 都没有 | 转发到客户管家客服群，进入等待回复状态 |
| - | 不以 YT 开头（图片/闲聊/表情等） | 一律忽略 |

### 方向② 客户管家 → 微信

- 只搬"**我转发的消息引来的**机器人（小圆）回复"，每条原文搬回微信群：
  - 回复带运单号 → 精确对应等待中的那单；
  - 回复不带运单号 → 对应最早一条等待中的转发；
  - **等待队列为空时**，小圆回复别人的消息、人工客服的消息一律不搬；
  - 搬回一条后刷新该单计时：小圆对同一单连发多条（如"已上报"→"已修改成功"）会全部搬回。
- **30 秒静默超时**：转发（或最后一条回复）后 30 秒无小圆新回复，本轮等待结束，
  之后迟到的回复不再搬运（日志提醒到客户管家查看）。
- 图片等非文本消息（不管哪边）一律当没看见。

## 文件说明

| 文件 | 说明 |
|---|---|
| `wechat_forwarder.py` | 核心业务逻辑：判定规则、待回复队列、主循环、Mock 演示 |
| `gui.py` | 配置窗口：微信群名、客服群名、客服名、屏蔽词、@客服词句 |
| `config.json` | 配置文件（由配置窗口生成，也可手工编辑） |

## 运行

```bash
# 1. 打开配置窗口，填写群名与关键词
python gui.py

# 2. Mock 演示：验证全部业务分支（不操作真实微信）
python wechat_forwarder.py
```

依赖：仅 Python 3.8+ 标准库（tkinter 随官方 Python 附带）。

## 当前状态与对接说明

核心逻辑与配置窗口已完成并通过 Mock 自测；**真实对接微信与客户管家窗口的适配层尚未实现**。
`wechat_forwarder.py` 中预留了四个接口：

- `WxSource.fetch_new()` —— 读取微信群新消息
- `WxSink.send()` —— 在微信群发送
- `KfSource.fetch_replies()` —— 读取客户管家里机器人的新回复
- `KfSink.send()` —— 在客服群发送

后续接入真实窗口时，用 `uiautomation` 实现这四个类替换 Mock 即可，主循环与判定逻辑不用动。

## 原程序说明（逆向结论）

- `1232.exe` 为 Delphi 编写并加 VMProtect 壳的加载器，内嵌易语言静态编译的业务主程序
  （调用大漠插件做找图找色与窗口操作）；
- 同目录 `dmyb.dll`（大漠插件）、`cfg.ini`（找色配置）、`客服来信息*.bmp`（找图模板）为其配套文件；
- **注意**：该文件夹中还混有伪装成 Synaptics 驱动的键盘钩子木马组件（`KBHKS.dll` 等）与
  带 VBA 宏的 XLSM 下载器，请勿运行原程序及其来路不明的组件；本 Python 版与其无任何关联。
